# Why mdl-1954 Returned Only Generic Placeholders

## Summary

Case **mdl-1954** produced only generic actor placeholders (Witness, Attorney, Judge, Court Clerk) with no actual named parties because **all 4 extraction sources failed**:

1. ❌ Database lookup skipped (non-matching case_id format)
2. ❌ Caption parsing failed (MDL documents have no party captions)
3. ❌ Confirmation notices missing (directory doesn't exist)
4. ❌ LLM validation had nothing to validate

## Root Cause: MDL Procedural Documents

The documents in mdl-1954 are **MDL (Multi-District Litigation) procedural orders**, not individual plaintiff complaints. These documents have fundamentally different structure:

### Standard Case Document (case_95):
```
SUPREME COURT OF THE STATE OF NEW YORK
COUNTY OF NEW YORK
----------------------------------------X

BONNIE DARLING,                    ← Named plaintiff
                    Plaintiff,

         -against-                 ← Separator

L'ORÉAL USA, INC.,                ← Named defendants
GOLDWELL,
KAO USA, INC.,
                    Defendants.

----------------------------------------X
```

### MDL Document (mdl-1954):
```
IN RE: NUVARING® LITIGATION       ← Litigation caption, not parties

SUPERIOR COURT OF NEW JERSEY
CASE NO. 284 (MT)
CIVIL ACTION

CASE MANAGEMENT ORDER NO. 35
REGARDING SETTLEMENT AGREEMENT
```

**Key Difference:** MDL documents reference "plaintiffs" and "defendants" generically but **don't list individual party names** on the first page.

## What Could Have Been Extracted

If we look at the document body text, there ARE party references:

### Document Text Analysis:

**Judge Found (doc_003 title_candidates):**
```
"BEFORE: HON. BRIAN R. MARTINOTTI, JSC"
```

**Defendant Found (paragraph text):**
```
"Organon USA, Inc. ("Organon")"
```

**Counsel References (generic):**
```
"Negotiating Plaintiffs' Counsel"
"a committee of plaintiffs' counsel"
```

### Why These Weren't Extracted:

1. **Judge in title_candidates, not confirmation regex:**
   - `title_candidates` is for LLM title identification, not actor extraction
   - Confirmation regex expects: `Assigned Judge:\s*(.+)` (e-filing format)
   - Actual text: `BEFORE: HON. BRIAN R. MARTINOTTI, JSC` (different format)

2. **Organon in paragraph 1, not caption block:**
   - Caption parser only looks at **first-page lines between role markers**
   - Organon appears in **paragraph text after the header**
   - No parser currently extracts entities from body paragraphs (that's Stage 2's job)

3. **Generic counsel references:**
   - "Negotiating Plaintiffs' Counsel" is a committee name, not an individual
   - Current parser expects individual names (e.g., "JONATHAN MICHAEL SEDGH")

---

## Could LLM Validation Have Helped?

**No.** LLM validation only works when there's **something to validate**.

The validation step:
1. Receives candidate roster from regex/heuristic extraction
2. Corrects roles, drops junk, rephrases labels
3. Returns cleaned roster

In mdl-1954, Step 1 produced **zero candidates**, so there was nothing for the LLM to validate.

Even if we sent the empty roster to the LLM:
```json
{
  "actors": []
}
```

The LLM would return:
```json
{
  "actors": []
}
```

Because it can only validate **candidates it's given**, not extract new actors from scratch.

## How to Fix This

### Option 1: Add MDL-Specific Caption Parser

**Location:** `utils.py` - new function `parse_mdl_caption()`

**Algorithm:**
1. Look for `IN RE: (.*?) LITIGATION` pattern
2. Extract defendant from first paragraph: `([A-Z][A-Za-z., ]+)\s+\(".*?"\)`
3. Extract judge from `BEFORE:.*?HON\.\s+([A-Z][A-Za-z. ]+)`

**Pros:** Targeted extraction for MDL documents

**Cons:** Adds complexity, only helps MDL cases

---

### Option 2: Use LLM for Entity Extraction (Not Just Validation)

**New Function:** `extract_actors_with_llm()`

**Algorithm:**
1. If regex extraction returns empty
2. Send first-page text + case context to LLM
3. Ask LLM to extract parties directly from text

**Prompt Example:**
```
Extract party names from this legal document:

DOCUMENT:
IN RE: NUVARING® LITIGATION
CASE MANAGEMENT ORDER NO. 35
...

This Court is advised that Organon USA, Inc. ("Organon") and a committee
of plaintiffs' counsel appointed by this Court...

Extract:
- Defendants: [list names]
- Judges: [list names]
- Attorneys: [list names]
```

**Pros:** Handles non-standard formats, extracts from body text

**Cons:** Slower, requires LLM server, less deterministic

---

### Option 3: Stage 2 Fallback - Extract Actors from Entities

**Algorithm:**
1. After Stage 2 runs GLiNER on body text
2. Find entities labeled "defendant", "judge", "attorney" (generic labels)
3. Back-fill actors.json with these entities
4. Re-run Stage 2 with updated dynamic labels

**Pros:** Leverages existing entity detection, no caption parsing needed

**Cons:** Circular dependency, requires two-pass processing

---

### Option 4: Database Import for MDL Cases

**Algorithm:**
1. Import MDL master case list to database
2. Link "mdl-1954" → actual database record
3. Use database as primary source (bypass caption parsing)

**Pros:** Authoritative source, works for all MDL cases

**Cons:** Requires database schema changes, MDL data source

---

## Recommended Approach

**For Production:** Option 2 (LLM extraction as fallback)

**Implementation:**
```python
# In stage_1_metadata.py, after all sources scanned:

if not actors and config.get("extract_actors_with_llm_fallback", False):
    logger.info("→ No actors found via regex, trying LLM extraction...")

```

**Why This Works:**

- Only runs when needed (empty roster)
- Leverages existing LLM infrastructure

## Key Takeaway

The extraction pipeline is **designed for individual case filings** (complaints, motions, answers) with standard caption blocks. MDL **procedural documents** (case management orders, settlement agreements) have fundamentally different structure and require different extraction strategies.

**Current State:**
- ✅ Works excellently for individual case filings (case_95)
- ❌ Fails for MDL coordination documents (mdl-1954)

**To Support MDL:**
- Add LLM-based fallback extraction
- OR add MDL-specific caption parser
- OR import MDL master party lists to database
